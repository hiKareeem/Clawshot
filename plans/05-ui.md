# UI architecture

Round 11 Track D. Product/visual decisions are in `decisions.md` (D36/D37); exercised evidence and
review choices are in `rounds/r11-ui.md`. The generator remains the sole gameplay authority.

## Boundaries

`clawshot.app` contains metadata, validation, read-only source detection, cancellable generation
and a verified per-seed Player. It imports public generator/patch/pack functions; it contains no
HTML, GUI calls, new fill algorithm or gameplay default.

`clawshot.ui` is a standard-library HTTP adapter plus local plain HTML/CSS/JavaScript. The CLI
starts on 127.0.0.1 with an OS-selected port. Normal startup chooses optional BSD pywebview or
the default browser. `--no-open` starts neither and disables Browse, Open and Play.

The actual generation worker uses the CLI's existing sequence:

1. Validate canonical Settings and paths; `pack.check_version` identifies the supported dump.
2. `pack.source.local_romfs` reads the folder directly or creates a private disposable NUP cache.
3. Run gift `seed_setup` when required, just as the CLI does.
4. `patch.make_seed` performs census, remake pool, fill/search and patch planning.
5. `patch.write_seed` writes verified resources, spoiler and play note into private staging.
6. Parent hashes the completed seed with the pack's tree_digest, exclusively reserves a new output
   folder, then moves stage/seed into output/seed and writes clawshot-seed.json. Publication is
   serialized with cancellation. Existing or concurrently created outputs are never replaced.

The detector imports `pack.hookshot.detect` directly; its HOS_MODS marker alone decides support.
The detector stand-in is removed. The required public-API extraction in `pack.runtime` exposes
`launch_plan(root, hookshot)` and `start_game(plan)`: private pack Play and UI Play now share one
mod-layout, save/log and environment implementation. The pack waits for the process; the UI keeps
its process handle and remains responsive. No loader code was copied into the UI.

The shared starter checks the Windows process list through the system tasklist executable
(no dependency or console window). A case-insensitive exact hookshot.exe match blocks before
any save/log write; a failed process check refuses rather than launching unchecked. Fake-lister
tests exercise the global refusal without starting a game. Pure launch plans remain inspectable
while a game is running.

## Application API

| API | Contract |
|---|---|
| `schema()` | Every Settings dataclass field, with key/label/kind/choices/default/help/group, per-choice labels/help/held reasons, presentation and dependency metadata. Defaults come from Settings/data settings, not JS. Missing/stale metadata refuses. |
| `validate(values=... | text=..., spec=None)` | Enforce types, supported choices and slice requirements; compile with the actual logic oracle. Full effective gift-kind groups in a spoiler CS1 normalize to player-facing Gift, then the seed pipeline rebuilds its own policy. `spec` is Python-only for custom/synthetic worlds. |
| `settings_payload(settings)` | Full form values, the generator's canonical CS1 and reasons for currently inactive fields. Inactive values survive replay. |
| `input_schema()`, `presets(spec=None)` | Application-input/stage descriptions and reviewed data-defined presets. No frontend field list. |
| `detect_dump(path)` | Read-only romfs/NUP supported-build fingerprint check; native path/kind/build result. |
| `detect_hookshot(path)` | Native JSON projection of frozen HookshotInfo fields: folder, exe, version, romfs, nups, supports_mods, reason. No executable is run. |
| `GenerationRequest(dump, output, seed, settings, hookshot='')` | Absolute local paths, exact integer seed, CS1; optional Hookshot path protects its installation from output overlap. |
| `Jobs.start(request)`, `snapshot()`, `cancel()`, `close()` | At most one spawned worker. Snapshots contain lifecycle status, stage status/elapsed seconds, original error type/message and a spoiler-free result summary. `close` cancels/joins. |
| `play_plan(result, hookshot)` | Read-only: verify the saved manifest's supported build and seed digest, sole real-folder mod and detected Hookshot support; return the shared command/cwd/environment/user/log plan. No original dump dependency. |
| `Player.start(result, hookshot)`, `snapshot()` | Windows-only explicit native action; at most one active game, per-output saves/log. No game is terminated when the UI closes. |
| `SeedLibrary.entries()`, `get(output, verify=True)` | List manifest metadata only, newest manifest mtime first, filtering to information files or older seed/romfs/romfs layouts. View verifies contents; Play's plan independently verifies. Known candidates alone authorize document/native actions. |
| `Preferences(path=None)` | Atomic path-only JSON in OS user config; explicit None is in-memory for embedded/test servers. No configuration in the source checkout. |

Python-only worker injection in `Jobs` supports deterministic synthetic-world tests. Neither a
worker callable nor a custom world can be selected through HTTP. A worker must produce the three
completed output entries under its assigned private stage/seed directory.

## Lifecycle and ownership

Job states: idle → running → succeeded/failed, or running → cancelling → cancelled. A finished
publication wins a cancellation race; its completed output is retained. A failed/cancelled worker
never publishes an unfinished seed. There are no extra fill retries or success fallbacks.

The multiprocessing **spawn** context is used on every platform. A parent monitor thread watches
both the pipe and process sentinel: early Windows termination can leave a duplicated pipe handle,
so waiting for EOF alone is not sufficient. Cancellation terminates only that process; after join,
the parent removes only the private staging/cache directory it created. A force-killed parent may
leave a private staging remnant; it does not authorize deleting other output folders.

Timings/progress are volatile application state, never written into deterministic seed files.
The fill and all read-back/beatability oracles remain unchanged. An empty or existing output
folder is not reused. The only auto-created parent is the suggested Documents/Clawshot directory,
after output protection checks and on Generate, not on browsing or schema discovery.

Each finished output has a format-1 clawshot-seed.json: seed, settings_string, output_sha256,
clawshot_version, game_build and the existing shuffled/resources/spheres counters. It contains
no original dump path. The digest covers only output/seed; the manifest, saves and log are outside
that tree. Exact manifest keys and types are checked before data reaches catalog authority.
Only the supported build and unchanged seed contents are required for saved-seed Play. Library
selection returns a loaded result with no fabricated generation stages/timings.
Catalog refresh never hashes seed contents. Legacy layouts without a manifest are not playable
and receive a calm regeneration instruction; unrelated folders are silently ignored. Modification
times affect only display order, never output contents or digest. Open/note actions need catalog
membership but not a content hash; View and the shared Play plan perform full verification.

## HTTP contract

Every URL starts `/s/<per-run-token>/`. The only static routes are that root, `app.js` and
`style.css`; no filesystem path is routed. API routes additionally require
`X-Clawshot-Token: <token>`. Requests use the exact bound Host and same Origin (when supplied).
Cross-site requests and non-ASCII/incorrect tokens are refused; no CORS access is granted.
JSON POST bodies require `Content-Type: application/json`, an object, and 1..65536 bytes.

| Method / `api/` route | Payload / result |
|---|---|
| GET `schema` | Schema, descriptions, versioned share strings, presets, capabilities, remembered inputs, initial stages and Recommended settings payload. |
| POST `settings` | Either `{values: {...}}` or `{settings_string: 'CS1...'}` → normalized settings payload. |
| POST `import-settings` / `shared-seed` | Version-bound player settings string, plus seed integer for shared-seed. Validate matching generator version and return canonical/settings/share payload; no job or file writes. |
| POST `detect` | `{dump?: path, hookshot?: path}` → read-only detection results. |
| POST `normalize-path` | `{path, kind?: 'dump'|'hookshot'|'output'}` → native absolute path. Read-only inputs resolve links; output remains link-free. No write. |
| POST `browse` | `{kind: 'dump-folder'|'dump-file'|'hookshot'|'output'|'seeds'|'emulator_mods', seed?: integer}` → selected native path or null. Output appends seed-N; seeds/mod-folder choices remember their roots. No seed directory is created; disabled in --no-open. |
| POST `generate` | GenerationRequest fields → current job snapshot. |
| GET `job` | Generation snapshot plus Player state; poll only during generation or a running game. |
| POST `cancel` | `{}` → cancellation/current terminal snapshot. |
| GET `seeds` | Metadata-only catalog entries, newest manifest first, remembered folders and any preferences warning. No content digest reads. |
| POST `select-seed` | `{output: known-folder|null}` → loaded seed or return to editing. Refused during generation; invalid entries cannot be selected. |
| POST `play` | `{hookshot, output?: known-folder}` → start the selected/completed/known catalog seed and return Player state. No arbitrary command/path. Refused in --no-open and outside Windows. |
| POST `result` | `{file: 'note'|'spoiler', output?: known-folder, confirmed?: true}` → fixed document text. Spoiler needs explicit true. |
| POST `open` | `{target: 'folder', output?: known-folder}` → open only a known output's seed folder with the OS handler; no shell. Disabled in --no-open. |
| POST `choose-eden` | Explicitly remember the known Eden game folder only if it exists. Native-capable sessions only; never assumed. |
| POST `copy-emulator` | `{output?: known-folder, confirmed: true}` → verified real-folder copy to the previously picked mod folder as Clawshot-seed-N/romfs. Exclusive mkdir, copied digest check, no replacement or emulator launch; disabled in --no-open. |

Invalid application requests return400, missing/invalid local authorization403, unknown routes404.
Responses are no-store, no-referrer and nosniff, with a self-only content policy and no framing.
The URL token is not an account/login boundary against other processes with the user's privileges;
it prevents an unrelated website or guessed local endpoint from driving file actions.

## Native dialog boundary

Dialogs are capabilities installed only by normal startup. In a pywebview session, a click calls
its window's native file/folder picker through the authenticated adapter. Browser mode queues
that click to a main-thread broker; tkinter is imported and a hidden Tk owner created only for
that request, then destroyed. The page sends its own screen rectangle and the Tk owner is a 1x1
borderless window at its center, so the dialog opens over the page. macOS never loads Tk in the
server: Tk turned the server into a Cocoa app whose events nobody pumped between dialogs, so after a
dialog it could stay frontmost and unresponsive, and its hidden owner put the panel in a screen corner.
There the broker runs `osascript` (`choose file`/`choose folder`), a short-lived process that
activates itself, shows the standard panel in front, and hands focus back when it exits.
Only one picker can be open. Cancellation returns null. Missing Tk/backend errors retain the
pasteable text path; there is no upload/server filesystem browser.
Pywebview uses FileDialog.OPEN/FOLDER when available, with legacy names only for older versions.
The input picker resolves library links; the output picker refuses them.

Tests inject a synthetic picker and exercise the real HTTP guards, selection validation and
non-mutation. Owner evidence confirms the base pywebview window and folder picker only, not the
file picker, browser/Tk or new Play. Normal startup enables Browse/Open/Play capabilities;
--no-open enables none. Play tests inspect plans and never invoke the game.

## Frontend extension points

`app/settings.toml` is exhaustive for Settings; each enumerated choice also requires nonblank
`choice_help`. `enabled_when` is a conjunction of named contains/equals/greater_than conditions
with reasons, evaluated by the app and returned as inactive fields. JS dims those controls but
keeps their values. Choice holds are separate: they remain visible, explain why they cannot be
chosen, and fail app validation. Presets are data, not duplicated JavaScript defaults.

Check counts are not copied into schema prose: generation's result is authoritative. Gift additions
therefore require no UI count change or duplicate eligibility policy.

Schema groups generate section headings. Multi-choice fields choose card presentation through
metadata; their status labels are data (Shuffled/Vanilla or Skipped/Plays). Keyboard focus/hover
shows the setting's or card's own schema help. Navigation excludes disabled child controls while
leaving explanatory rows/cards focusable. Hint verbs reflect only actions that can work now.
Text editors do not consume Q/E as tab commands.

All colors and both approved font stacks are in `style.css`'s `:root` block. Typography uses only
installed fonts, no downloaded assets. Recheck long labels/paths, focus contrast, unavailable and
inactive states, and 1280×860 idle/running/finished geometry after restyling. A bundled font needs
a maintainer licence decision; OFL is not in rule7's current accepted list. See `docs/ui.md` for
contributor steps and the explicit not-done list, including gamepad/Steam Deck input.
